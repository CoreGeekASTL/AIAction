| 19 | 数组/缓冲区边界 | 对数组或缓冲区进行写入操作时，必须显式校验写入长度不超过容量 | — | 需人工评审 | 评审拦截 |

## 三、建议规则（违反仅出报告）

> 指导性条目，违反不拦截，差距报告中单列提示改进。

| 编号 | 规范维度 | 规范要求（含必须/禁止） | 参数 | 检查方式 |
| :---: | :--- | :--- | :---: | :---: |
| 1 | 命名意图 | 类名、变量名、函数名必须完整揭示其用途和意图，禁止使用拼音、无意义单字母（循环索引 `i`/`j` 除外）及模糊缩写（如 `data`、`temp`） | — | 需人工评审 |
| 2 | 布尔命名规范 | 布尔类型变量或返回布尔值的函数，必须带有 `is` / `has` / `can` / `should` 等明确语义前缀，禁止使用 `flag` 或 `status` 等无含义命名 | — | 可机器检查 |
| 3 | 函数规模 | 单个函数（含注释及空行）总行数不得超过设定上限 | 50 | 可机器检查 |
| 4 | 逻辑复杂度 | 单个函数的圈复杂度（独立路径条数）不得超过设定上限 | 10 | 可机器检查 |
| 5 | 接口文件规模 | 单个接口定义/头文件总行数不得超过设定上限 | 2000 | 可机器检查 |
| 6 | 实现文件规模 | 单个实现文件/源文件总行数不得超过设定上限 | 4000 | 可机器检查 |
| 7 | 代码缩进 | 缩进必须使用空格，且每一级缩进的空格数固定为设定值 | 4 | 可机器检查 |
| 8 | 变量初始化 | 局部变量必须在声明语句中同时完成初始化，禁止声明与赋值分离 | — | 可机器检查 |
| 9 | 注释内容哲学 | 注释仅允许解释业务逻辑缘由（Why）或设计约束（Why not），**禁止**复述代码行为（What）；同时禁止保留任何被注释掉的废弃代码 | — | 需人工评审 |
| 11 | 异常使用范围 | 异常机制仅限用于不可恢复的致命错误，禁止用于常规业务分支或流程控制 | — | 需人工评审 |
| 12 | 递归限制 | 禁止不可控递归；若允许递归，最大调用深度不得超过设定值（0 表示完全禁止） | 0 | 可机器检查 |
| 13 | 魔法数字 | 业务逻辑代码中禁止直接出现 0 / 1 / -1 等字面量（循环计数器除外） | — | 可机器检查 |
| 14 | 空值检查距离 | 对指针/引用/可空对象解引用或调用前，必须在设定行数内完成非空校验 | 3 | 可机器检查 |
| 15 | 资源释放后处理 | 动态内存/文件句柄/连接等资源释放后，对应变量必须立即置为无效值（如 `null`） | — | 可机器检查 |
| 16 | 函数参数个数 | 单个函数的形参数量不得超过设定上限 | 5 | 可机器检查 |
| 17 | 嵌套深度 | 条件判断（`if`/`else`）与循环（`for`/`while`）相互嵌套的总层数不得超过设定上限 | 4 | 可机器检查 |
| 18 | 跳转语句（`goto`） | 禁止使用 `goto` 向上跳转；仅允许在单函数内向下跳转至统一错误处理出口 | — | 可机器检查 |
| 20 | 单一职责（模块级） | 单个模块/类的修改原因（职责）不得超过设定个数（1 表示严格单一职责） | 1 | 需人工评审 |
| 21 | 逻辑抽象层级（SLAP） | 单个函数体内的语句必须处于同一抽象层级，禁止高层业务逻辑与底层实现细节混写 | — | 需人工评审 |
| 22 | DRY（无重复逻辑） | 禁止在两处及以上位置出现相同的业务逻辑片段，必须抽取为公共函数或工具类 | — | 可机器检查 |
| 23 | 迪米特法则（方法链） | 禁止连续调用超过设定层数的方法/属性链（如 `a.getB().getC().do()`），避免暴露内部结构 | 2 | 可机器检查 |
| 24 | 布尔参数传递 | 禁止传递布尔值作为函数参数来切换内部两种不同行为，应拆分为两个独立函数 | — | 可机器检查 |
| 25 | 命令查询分离（CQS） | 执行写操作的函数**禁止**返回查询结果；执行读操作的函数**禁止**修改内部状态 | — | 需人工评审 |
| 26 | 副作用隔离 | 函数体内禁止对外部全局状态（含静态变量、外部文件、数据库）产生非预期的隐蔽副作用 | — | 需人工评审 |
| 27 | 测试用例命名规范 | 单元测试函数命名必须采用 `should[预期行为]_When[触发条件]` 格式，禁止使用 `test1` / `case2` 等无意义命名 | — | 可机器检查 |
| G2 | context 传递 | 跨层/跨 goroutine 调用第一个参数传 `ctx context.Context`，禁止传 `nil`（根处用 `context.Background()`/`context.TODO()`）；禁止把 ctx 存入结构体字段长期持有 | — | 可机器检查 |
| G5 | defer 资源配对 | 文件/连接/锁/响应体获取成功后立即 `defer` 配对释放，`defer` 必须写在 error 检查**之后**；`defer` 中忽略返回值须显式 `_ =`；**禁止在长循环内堆积 `defer`** | — | 可机器检查 |
| G6 | 单例与包级状态 | 单例初始化必须 `sync.Once` 保护，禁止"判空即建"式裸懒初始化（并发不安全）；包级可写变量须有并发保护说明 | — | 可机器检查 |
| G7 | 接口惯例 | 接口在使用方包定义（accept interfaces），实现方加编译期断言 `var _ Iface = &impl{}`；接口方法数克制（≤5），超大接口按使用场景拆分 | — | 需人工评审 |
| G9 | init 与注册 | `init()` 仅用于轻量注册（如 `orm.RegisterModel`、驱动注册），禁止 IO/网络等重逻辑；实体须 `TableName()` + `init()` 注册 + orm tag 完整 | — | 需人工评审 |
| G10 | 时间与数值字面量 | 时长必须用 `time.Duration` 乘法表达（`30 * time.Minute`），禁止魔法秒数；时间格式串提取为常量 | — | 可机器检查 |
| G11 | 版权声明头 | Go 源文件首行必须带版权声明 `// Copyright (c) Huawei Technologies Co., Ltd. 2026.`（存量文件沿用其既有年份格式） | — | 可机器检查 |
| G12 | Beego 实体注册约定 | DB 实体必须带完整 `orm:"pk;column(xxx)"` tag + `TableName()` 方法 + `init(){ orm.RegisterModel() }` 注册；Beego 不支持复合主键，复合唯一约束用 DDL UNIQUE INDEX 兜底 | — | 可机器检查 |
| G13 | DAO/Service 分层约定 | DAO 继承 `BaseInterface` 并设置 `EntityType`；Service 采用「接口 + 小写实现类 + 包级变量 + sync.Once」模式；禁止 Controller 直接访问 DAO | — | 需人工评审 |
| G14 | 出站 HTTP 调用约定 | HTTP 出站请求优先使用 `common/https` 的 `NewRequest().WithRetry()` builder；本地 IP 获取用 `https.GetLocalIP`；UUID 生成统一用 `github.com/google/uuid.New()` | — | 可机器检查 |
| P1 | 资源释放（testsuit/） | 文件/连接/锁必须用 `with` 上下文管理器，禁止裸 `open()` 不配 `close` | — | 可机器检查 |
| P2 | 异常处理（testsuit/） | 禁止裸 `except:` 与 `except Exception: pass` 吞异常；异常捕获必须具体到类型并带日志 | — | 可机器检查 |
| P3 | 可变默认参数（testsuit/） | 函数默认参数禁止用可变对象（`def f(x=[])`），用 `None` + 函数内初始化 | — | 可机器检查 |
| P4 | 全局状态（testsuit/） | 禁止模块级可变全局变量被多函数隐式改写；必须共享时用显式封装（类/闭包/锁） | — | 需人工评审 |
| P5 | 类型与命名（testsuit/） | 公共函数带类型注解（入参/返回值）；snake_case 命名，禁止 camelCase 混入 | — | 可机器检查 |
