# Skill: sw-architecture-design

# 系统架构设计 Skill

根据 SE 需求文档、接口文档，生成系统架构设计文档，供后续服务架构设计使用。

## 何时使用

- 需要根据 SE 需求文档创建系统架构设计文档
- 需要根据接口文档补充技术细节
- 需要分析存量代码，确认可复用模块、技术栈、代码约定
- 需要明确整体架构、数据流、接口契约、DB 表结构、配置项

## 与上下游的关系

```
SE 需求文档 + 接口文档
   ↓ [sw-architecture-design] ← 当前 skill
系统架构设计文档
   ↓ 状态报告（DONE / DONE_WITH_CONCERNS）
   ↓ [sw-service-architecture-design] ← 下一个 skill
服务架构设计文档
   ↓ [story-detail-design]
Story 详设文档
   ↓ [code-generation-quality-loop]
代码实现
```

## 用户需提供

- **需求描述**：简要描述本次设计的目标功能（如"实现GIDS选主机制和SNMP告警上报"）
- **代码仓库路径**：当前代码仓库路径（用于分析现有实现）

## 必须遵守

1. **必须使用 doc-loader 精准检索文档**，避免全量加载文档库
2. **必须梳理存量代码**，确认可复用模块、技术栈、代码约定
3. 遵循现有代码库的技术栈、框架、命名约定
4. 遗留问题清单直接放在设计文档末尾，不单独文件
5. 所有设计决策必须有依据（需求引用或接口规范）
6. 代码示例必须与现有代码风格一致
7. 完成后必须输出状态报告（DONE / DONE_WITH_CONCERNS），交接给服务架构设计

## 实施步骤

> 详细操作指南参见 [reference/implementation-steps.md](reference/implementation-steps.md)

| 步骤 | 概要 |
| --- | --- |
| 第一步：doc-loader 检索 | 启动 doc-loader agent 分析需求，按优先级加载规格文档，提取关键信息 |
| 第二步：梳理存量代码 | 分析数据库交互流程、可复用模块、技术栈、代码约定 |
| 第三步：生成架构设计文档 | 按模板生成文档（需求背景/整体设计/接口设计/DB表结构/配置项） |
| 第四步：检查清单 | 7 项检查 |
| 第五步：输出状态报告 | DONE / DONE_WITH_CONCERNS，交接给服务架构设计 |

## 验收标准

- [ ] 文档包含需求背景、整体设计、接口设计、DB表结构设计、配置项
- [ ] 架构总览图清晰（mermaid flowchart）
- [ ] 数据流图完整
- [ ] 接口设计与接口规范一致
- [ ] DB 表结构有并发分析和锁机制设计
- [ ] 配置项已列出
- [ ] 存量代码分析已完成
- [ ] 输出状态报告（DONE / DONE_WITH_CONCERNS）
- [ ] 设计要素标注完整：所有承载设计要素的章节均有 `> **承载设计要素**` 标注
- [ ] 核心设计要素非空：C1 / C2 / D2 / D3 / R1 / R3 六项核心要素有实质内容
