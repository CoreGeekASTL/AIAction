# Skill: sw-service-architecture-design

# 服务架构设计 Skill

基于系统架构设计文档，生成服务架构设计文档，包含架构约束规则、Story 拆分、架构约束校验、DT 测试设计、风险评估和遗留问题。

## 何时使用

- 已有系统架构设计文档（由 sw-architecture-design 生成），需要做 Story 拆分
- 需要明确实现时遵循的架构约束（分层改造顺序、设计模式、并发模型、事务边界等）
- 需要拆分 Story 并校验拆分合理性

## 与上下游的关系

```
SE 需求文档 + 接口文档
   ↓ [sw-architecture-design] ← 上一个 skill
系统架构设计文档
   ↓ 状态报告（DONE / DONE_WITH_CONCERNS）
   ↓ [sw-service-architecture-design] ← 当前 skill
服务架构设计文档（架构约束 + Story 拆分 + 约束校验 + DT 测试 + 风险 + 遗留）
   ↓ [story-detail-design] ← 下一个 skill
Story 详设文档
   ↓ [code-generation-quality-loop]
代码实现
```

## 用户需提供

- **系统架构设计文档路径**：由 sw-architecture-design 生成的文档
- **需求描述**：简要描述本次设计的目标功能
- **代码仓库路径**：当前代码仓库路径

## 必须遵守

1. **架构约束规则必须前置**：在 Story 拆分之前明确分层改造顺序、设计模式选型、并发模型、事务边界等约束依据
2. **Story 按功能特性拆分**（非技术分层），每个 Story 端到端交付一个业务功能
3. **Story 可独立验收**，功能 Story 并行依赖基础 Story，避免串行依赖链
4. 每个 Story 的开发任务按分层改造顺序排列（先接口→再 DAO→再 Service→最后 Controller）
5. 遗留问题清单直接放在设计文档末尾，不单独文件
6. 所有设计决策必须有依据（需求引用或架构设计引用）
7. 完成后输出状态报告（DONE / DONE_WITH_CONCERNS）

## 验收标准

- [ ] 文档包含架构约束规则、Story 拆分、Story 详细设计引用、架构约束校验、DT 测试设计、风险评估、遗留问题
- [ ] **架构约束规则前置**（分层改造顺序/设计模式/并发/事务等在 Story 拆分之前）
- [ ] Story 按功能特性拆分（非技术分层），每个 Story 端到端交付业务功能
- [ ] Story 可独立验收，功能 Story 并行依赖基础 Story，无串行依赖链
- [ ] Story 依赖关系图清晰
- [ ] 架构约束校验（Story拆分合理性/分层改造顺序/并发安全/事务边界/设计模式/线程池回收）全部完成
- [ ] DT 测试设计包含 Mock 方案
- [ ] 风险评估已列出
- [ ] 遗留问题已列出并标注状态
- [ ] 设计要素标注完整
- [ ] 核心设计要素非空：M5 / C2 / R5 / R6 四项核心要素有实质内容

## 设计理念

> **约束先行，Story 基于约束**：服务架构设计不是上来就拆 Story，而是先承载架构约束规则（分层改造顺序、设计模式、并发模型、事务边界等），然后基于约束做 Story 拆分，最后校验 Story 是否遵循约束。
